# 用户同步详细设计（现网对齐版）

## 1. 目标

确保平台用户、**工作空间**与外部系统（主要是 Grafana）的组织关系可关联、可追踪、可补偿。

## 2. 当前实现范围

平台内：

- **工作空间 + 成员 + 用户**（已移除 Department / 旧 Tenant 模块）
- 平台角色（`users.role`）：`admin` / `user`
- 工作空间角色（`ops_workspace_members.role`）：`admin` / `member` / `viewer`
- 用户登录走 JWT；亦可使用 API Token（`ops_api_tokens`）
- 前端 `WorkspaceSwitcher` + `useWorkspaceStore` 切换可见工作空间

外部集成：

- Grafana：组织、组织用户、数据源（`/grafana/orgs/*`）
- Grafana 多实例：`/grafana/instances`（按 `instance_id` 解析 client）
- 告警事件来自 Alertmanager Webhook（不再同步 N9E 用户体系）

约束：平台元数据是主数据源；外部状态由平台触发同步。

## 3. Bootstrap（首次部署）

- 接口：`POST /api/v1/users/bootstrap`
- 公共接口，**仅在系统中没有任何 admin 时允许**
- 已存在 admin → `409`
- 创建动作落审计

## 4. 工作空间成员 RBAC

`ops_workspace_members` 为工作空间权限主数据源：

| 字段 | 说明 |
|---|---|
| `workspace_id` | 所属工作空间 |
| `user_id` | 平台用户 |
| `role` | `admin` / `member` / `viewer` |
| `status` | 激活 / 软删 |

访问判定（概念）：

1. 平台 `admin` → 放行
2. 查成员表：viewer 可读；member/admin 可写（具体写接口仍可能额外要求平台 admin）
3. 无成员关系 → 拒绝跨空间访问

成员 API：

```
GET/POST   /workspaces/:id/members
PUT/DELETE /workspaces/:id/members/:userId
```

## 5. 用户增删改

| 操作 | 谁可以做 |
|---|---|
| 创建（POST /users） | 平台 admin |
| 删除（DELETE /users/:id） | 平台 admin |
| 修改自己（邮箱 / 手机 / 密码） | 本人 |
| 修改任意用户 / 角色 | 平台 admin |

密码哈希 bcrypt，`OPS_BCRYPT_COST`；密码字段不返回。用户模型无强制 `workspace_id` FK——归属由成员表表达。

## 6. 同步触发点

| 平台事件 | 外部联动 |
|---|---|
| 创建工作空间 | Grafana CreateOrg + WorkspaceProvisioner（VMRoute / VMUser / Datasource） |
| 删除工作空间 | Grafana DeleteOrg（最佳努力）+ 清理路由/资源 |
| 成员变更 | 前端可见性立即变化；Grafana Org 用户按需同步（以代码为准） |

## 7. 前端表现

- TopBar WorkspaceSwitcher：admin 可选「全部工作空间」
- 列表页按当前工作空间过滤（`workspace_id`）
- 侧栏「用户」「审计」仅平台 admin 显示

## 8. 残余与迁移

- 部分业务表列名仍为 `tenant_id`，值 = Workspace UUID
- 旧文档中的 `ops_tenant_members` / `AuthzService` / N9E 用户同步 **已废弃**
