# 云原生可观测性平台 — 总体设计文档（v4 SaaS 对齐版）

## 1. 定位

`ops-system` 是 **Datadog 式 SaaS 可观测控制面**（对齐 TCOP / 阿里云 UModel 演进方向），统一管理：

- **监控（Phase 1）**：VictoriaMetrics 共享 VMCluster 池 + vmauth 多租户 + VMAgent 采集
- **日志（Phase 1 数据面）**：Vector Agent → Kafka → Vector Aggregator → VictoriaLogs cluster；logstore 抽象预留 ClickHouse/Doris
- **链路（后续）**：Tempo / OTel
- **UModel 骨架**：Entity / MetricSet / DataLink 元数据，为跨 Pillar 关联打地基

告警计算不自研：N9E + VMRule 集成。

## 2. SaaS 多租户模型

```
Platform
 └── Zone（可用区监控面）
      └── Shared VMCluster 池（Helm k8s-stack + vmauth）
           └── Workspace → VMUser + ops_vm_routes
                └── Metric Workspace（Instance shared）
                     └── BusinessCluster → VMAgent → remoteWrite
```

**日志管道（Zone 级共享）**：

```
BusinessCluster → Vector Agent（U-001 标签）→ Kafka topic ops-logs-{zone}
  → Vector Aggregator（过滤/ops_signal）→ vlinsert → vlstorage → vlselect
  → ops-system logstore（LogsQL，强制 ops_tenant_id 过滤）
```

**唯一形态**：租户只拿 VMUser + 路由配额；独享（dedicated）模式已从代码与数据模型中删除。

## 3. UModel 骨架（Phase 1）

| 概念 | 表 | 说明 |
|---|---|---|
| Storage | `ops_vm_clusters` | Zone 共享指标池 URL 登记 |
| LogStorage | `ops_log_clusters` | Zone 共享日志管道（VL + Kafka + Aggregator） |
| Entity | `ops_entities` | service / k8s_cluster / workload 等 |
| MetricSet | `ops_metric_sets` | 指标集元数据 |
| LogSet | `ops_log_sets` | 日志集元数据 |
| DataLink | `ops_data_links` | Entity ↔ MetricSet / LogSet |

**强制标签（U-001）**：`ops_tenant_id`, `ops_zone`, `ops_workspace`, `ops_cluster`
