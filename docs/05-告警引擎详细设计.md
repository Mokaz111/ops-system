# 告警引擎详细设计（现网对齐版）

## 1. 定位

告警是平台 **一等公民**，不再依赖 N9E。

| 能力 | 实现 |
|---|---|
| 规则存储与 CRUD | PostgreSQL `ops_alert_rules` + `AlertService` |
| 规则评估 | 同步为 K8s **VMRule** CR（VMOperator） |
| 事件入库 | Alertmanager → `POST /api/v1/webhooks/alertmanager` |
| 通知 | `ops_notification_channels` + `notify` 投递 |
| 批量导入 | Prometheus 风格 YAML / Zip / tar.gz |
| 静默 | 前端占位；后端路由未实现（规划对接 Alertmanager Silence） |

接入中心模板仍可通过 `alert_spec` / VMRule 清单随安装下发规则（模板驱动路径与直接 CRUD 并存）。

## 2. 端到端链路

### 2.1 规则下发（直接 CRUD / 导入）

```
用户创建或导入规则（tenant_id 字段 = Workspace UUID）
          │
          ▼
AlertService 持久化 ops_alert_rules
          │
          ▼
vm.VMOperatorClient.ApplyAlertRule
   → VMRule CR（Name/Namespace/Expr/For/Severity/...）
          │
          ▼
VMOperator 评估 → Alertmanager
```

### 2.2 模板安装路径

```
接入中心 Install/Upgrade（parts 含 vmrule）
          │
          ▼
integration.applier.vmRuleApplier → Apply VMRule
   labels: managed-by=ops-system / template / installation
```

### 2.3 事件回流

```
Alertmanager webhook
          │
          ▼
POST /api/v1/webhooks/alertmanager  （公共，token 校验）
          │
          ▼
AlertEventService 写入 ops_alert_events
          │
          ▼
可选：按渠道 notify；前端事件页 ack
```

## 3. HTTP API

前缀 `/api/v1`。读接口 JWT；写接口多数 `RequireRole("admin")`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/alerts/rules` | 规则列表（支持 workspace/tenant 过滤） |
| POST | `/alerts/rules` | 创建规则 |
| POST | `/alerts/rules/import` | **批量导入**（multipart） |
| PUT/DELETE | `/alerts/rules/:id` | 更新/删除 |
| GET | `/alerts/events`、`/alerts/events/:id` | 事件 |
| PUT | `/alerts/events/:id/ack` | 确认 |
| GET/POST/PUT/DELETE | `/alerts/channels[/:id]` | 通知渠道 |
| GET | `/alerts/stats/{summary\|trend\|by-level\|by-rule}` | 统计 |
| POST | `/webhooks/alertmanager` | 事件入口 |

### 3.1 规则导入

- 表单字段：`file` + `tenant_id`（历史字段名，值为 Workspace UUID）
- 支持扩展名：`.yaml` / `.yml` / `.zip` / `.tar.gz`
- 限制（实现侧）：上传总量与单文件大小上限；单次解析 YAML 数量上限
- 语义：Prometheus `groups[].rules[]`；**跳过 recording rules** 与已存在重复规则
- severity：从 labels/annotations 映射为平台级别（critical/warning/info 等）
- 返回：导入成功/跳过/失败计数与明细（`ImportRulesResult`）

## 4. 权限与隔离

| 操作 | 平台 user | 平台 admin |
|---|:-:|:-:|
| 查询规则/事件/渠道/统计 | ✓（受工作空间可见性约束） | ✓ |
| 确认事件 | ✓（视成员权限实现） | ✓ |
| 创建/更新/删除规则与渠道、导入 | ✗ | ✓ |

工作空间隔离：列表过滤优先 `workspace_id`；持久化列可能仍名 `tenant_id`。

## 5. 前端信息架构

侧栏 **告警** 分组：

- 事件 `/alerts/events`
- 规则 `/alerts/rules`（含导入按钮、跳转渠道）
- 静默 `/alerts/silences`（占位说明）

`/alerts` 重定向到规则；通知渠道为子页。TopBar WorkspaceSwitcher 与规则/事件过滤联动。

## 6. InstanceDetail 告警 Tab

展示该实例由接入中心下发的 VMRule 与状态，并内链到平台告警规则/事件（不再跳转 N9E）。

## 7. 演进方向

- Alertmanager Silence API 对接，替换静默占位页
- 分组/抑制规则模板化
- 残余字段 `tenant_id` → `workspace_id` 迁移
- 事件页与 Instance firing 数联动加强

## 8. 运维要求

- 监控 webhook 失败率与 VMRule Apply 失败 revision
- 导入大文件时关注网关 body size 限制
- 文档与 UI 明确：评估在 VM 侧，平台负责编排、存储与通知闭环
