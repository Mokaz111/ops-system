# 后端详细设计（现网对齐版）

## 1. 技术栈

- Go + Gin
- GORM + PostgreSQL（主存储 + 审计）
- Redis（幂等键等，可选）
- client-go + Helm SDK
- Zap / Viper

## 2. 分层结构

```
backend/internal
├── handler         HTTP：绑定、错误映射、工作空间 / 角色断言
├── service         业务编排
│   ├── workspace_* / workspace_member_* / workspace_provisioner
│   ├── alert_* / alert_import / notification_*
│   ├── business_cluster_* / instance_* / log_instance_*
│   ├── integration_* / metric_* / zone_* / platform_*
│   └── umodel_* / api_token_* / audit_*
├── repository      GORM + scope
├── model           含 collect_config.go（Metrics/LogsCollectConfig）
├── middleware      JWTAuth（JWT 或 API Token）/ RateLimit / CORS / RequireRole
├── idempotency     Redis 幂等
├── integration     渲染器 + applier（k8s / grafana）
├── k8s / helm / grafana / vm / logagent / logstore / notify
└── server          NewRouter
```

已移除：`n9e` 包、Department/Tenant 服务主路径、旧 AuthzService/`ops_tenant_members` 作为现行 RBAC。

handler 不直接 import GORM；service 不直接处理 HTTP。

## 3. 路由与权限

### 3.1 鉴权层

| 层 | 中间件 | 范围 |
|---|---|---|
| 公共 | — | `/health`、`/api/v1/health[/db]`、`POST /auth/login`、`POST /users/bootstrap`、`POST /webhooks/alertmanager` |

## 4. 关键业务规则

### 4.1 工作空间隔离

- 查询参数优先 `workspace_id`
- handler 使用 `resolveWorkspaceScope` / `assertWorkspaceAccess` 与成员表校验
- **残余**：大量模型列仍名 `tenant_id`，存的是 Workspace UUID；数据面标签仍可能是 `ops_tenant_id`

### 4.2 角色模型

| 层级 | 角色 |
|---|---|
| 平台（`users.role`） | `admin` / `user` |
| 工作空间（`ops_workspace_members.role`） | `admin` / `member` / `viewer` |

平台 `admin` 跨空间；普通用户仅见所属工作空间。多数资源写接口当前仍收敛为平台 `admin`（成员写权限按模块逐步开放）。

### 4.3 Workspace Provisioning

创建工作空间后由 `WorkspaceProvisioner`：

1. 写 `ops_vm_routes`（insert/select/rule）
2. Apply VMUser CR + Secret
3. 注册默认 Datasource；联动 Grafana Org（最佳努力）

### 4.4 平台级扩容 / 共享初始化

- 仅注册目标；`dry_run` → `Idempotency-Key` apply
- Chart：`vm/victoria-metrics-k8s-stack`
- 审计：`platform_scale_audits`

### 4.5 接入中心

- 模板/版本/安装活跃唯一约束与 reinstall 语义不变
- 安装请求体中的 `tenant_id` 必须与目标实例所属工作空间一致
- applier 标签：`managed-by=ops-system` / `template` / `installation`

### 4.6 业务集群采集配置

字段存于 `ops_business_clusters.metrics_collect_config` / `logs_collect_config`（JSONB）。

**MetricsCollectConfig**：`select_all_by_default`、`scrape_interval`、`scrape_timeout`、`namespace_include` / `namespace_exclude`  
**LogsCollectConfig**：`namespace_include` / `namespace_exclude`、`exclude_paths`

- `GET/PUT .../collect-config`
- VMAgent / Vector YAML 构建读取上述配置
- `enable-logs` / `disable-logs` 控制日志采集

### 4.7 告警引擎

见 `05-告警引擎详细设计.md`：CRUD → VMRule；导入；Webhook → 事件；渠道通知。

### 4.8 指标库 / Bootstrap

- 指标按 `(component, name)` upsert；`manual_override` 不被 reparse 覆盖
- `POST /users/bootstrap` 仅系统无 admin 时允许，否则 409

## 5. 模型与索引（要点）

| 表 | 说明 |
|---|---|
| `ops_workspaces` | 工作空间 |
| `ops_workspace_members` | 成员角色 |
| `users` | 平台用户（role: admin/user）；无强制 workspace FK |
| `instances` | 监控实例（列名可能仍为 tenant_id） |
| `ops_log_instances` | 日志实例 |
| `ops_business_clusters` | 业务集群 + 采集配置 JSON |
| `ops_alert_rules` / `ops_alert_events` | 告警 |
| `ops_notification_channels` | 通知渠道 |
| `ops_entities` / `ops_metric_sets` / `ops_log_sets` / `ops_data_links` | UModel |
| `ops_integration_*` | 接入中心 |
| `ops_metrics` / mappings | 指标库 |
| `ops_grafana_instances` | Grafana（平台级，Org 映射隔离） |
| `ops_vm_clusters` / `ops_vm_routes` / `ops_datasources` | 指标控制面 |
| `ops_api_tokens` | API Token |
| `platform_scale_audits` | 平台扩容审计 |
| `ops_zones` / `clusters` | 可用区与 K8s |

软删统一 `deleted_at`；审计 revision / platform_scale 不软删。

## 6. 幂等与审计

- 头：`Idempotency-Key`；Redis NX；命中重放 `X-Idempotency-Replayed`
- 关键审计：平台扩容、接入 revision、通用 audit 列表

## 7. 错误处理与状态码

| HTTP | 典型场景 |
|---|---|
| 400 | 参数错误、分页非法 |
| 401 | 未登录 / token 无效 |
| 403 | 角色不足、跨工作空间 |
| 404 | 资源不存在 |
| 409 | 模板/版本/安装冲突、bootstrap 已存在 |
| 422 | 业务语义错误 |
| 429 | 限流 |
| 500 | 未分类（响应脱敏） |
| 503 | K8s/Helm/Grafana 等依赖不可用 |

## 8. 安全

- bcrypt：`OPS_BCRYPT_COST`
- JWT：`OPS_JWT_SECRET` ≥ 32；可与 API Token 并存认证
- CORS 白名单；限流按 IP
- Grafana 凭据加密列；日志不打印密钥
